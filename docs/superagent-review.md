# Super-agent 实现核对（2026-11-22）

核对来源：DeepSeek Harness 发布的 [Exploring Super-agent Design: Towards a More Autonomous Agent System](https://x.com/DeepSeekHarness/status/2116857257245987236)。原文讨论架构设想，并不宣称所有能力已经是产品功能。配套仓库是 [dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)。本次读取了全文，包括事件路由、全双工和 Watchdog 章节。

## 当前唤醒链路

行情采样 → 程序记录走势、运行策略规则 → 已归属品种的事件直接送到该品种 Worker 的信箱或正在执行的轮次 → Worker 判断并给计划 → 程序核成本、权限和风控后执行 → 任务、活动和回执落库。

用户对话 → Router 理解要求、读取全局状态或委派 → Worker 在独立的执行上下文中处理 → Router 汇总结果。对话交办的交易操作保留现有审批语义。

软事件的语义过滤由单独的轻量 Gate 执行，属于路由层的过滤功能；不是让常驻对话 Router 每次重新读一遍全局再转交。原文的订阅直通也允许程序将后续事件直接交给所属 Worker，所以直通本身不是架构错误。

Watchdog 的确定性循环检查存活和账户健康，既不是另一位交易决策者，也不是每 15 秒调用交易模型。

## 本次修复

- `always` 的旧兜底忽略 Worker 的下次检查时间，到最短间隔就重新复盘；改为尊重已给出的检查时间，硬事件仍可提前唤醒。
- 自动重试原先只调整普通复盘时间，留言和其他入口能绕过。独立的重试截止时间覆盖自动复盘和模拟盘预警调用，按 2 / 4 / 8 / 15 分钟退避；手动复盘仍可主动重试。
- 健康巡检不再等待平仓后的模型复盘和战绩整理；后台工作各自限时且不重复启动。平仓复盘一批最多尝试三笔，失败也计入。
- 恢复旧循环时先等待取消和清理结束，再启动替代任务；排队等待 Worker 锁的时间不算执行超时。恢复巡检自身出错也继续下一次检查。
- 失败恢复已读信箱；等待期间的不同硬事件合并保留，成功处理后确认，避免单一原因覆盖旧事件。
- 排队的交办任务取消后落库结束；Router 失败也在活动和对话中保留记录。
- 新错误保存脱敏的异常类型、正文、上游状态/模型/请求编号（异常提供时）、因果链和调用位置。正文每条上限 24000 字符，超出明确标记。`GET /api/work/{id}` 只读取当前交易环境；历史上已被截短的内容不能恢复。
- 交易页、工作台共享不做计划的原因说明，补齐 `no_edge` 并给未知原因兜底。进行中或失败时保留上一份报告，并标明“上次完成”。
- 交易对话打开、切换后定位到最新消息；用户上翻时暂停跟随，重新打开恢复。图片和容器重新获得高度时也调整位置。

## 尚未等同原文的部分

- Router 委派工具仍同步等待 Worker 结果，尚未实现原文 `start/stop → 完成事件` 的全双工工具协议。
- 对话 Router 的历史按 thread 保存；并发请求缺少统一的全局顺序和完整的跨任务事件引用。全局看板能读当前状态，不能替代事件引用图和长期上下文召回。
- Watchdog 仍与应用在同一进程，不能在整个进程退出后自行复活，也没有独立模型会话评估任务是否持续取得实质进展。部署级重启需要外部进程管理；语义进展评估需要另外设计预算和介入权限。
- 信箱和任务有持久化，但尚无一套完整的事件订阅、确认和重放协议。内存中的合并唤醒原因不是持久队列；重启后的延续能力不能描述成原文全部的持久能力。

上述部分是后续架构工作，不能用缩短轮询间隔或增加模型调用来冒充已经完成。本次没有调整交易候选算法、回测门槛或实盘权限。

## 2026-11-23 叫醒方式调整

依据是 11-21 16:14 到 11-22 12:13 的运行记录：1068 轮复盘里约九成由定时轮询触发，81% 的结论和上一轮完全一样；
595 条观察线里 576 条被下一轮复盘撤掉重设，中位只存在 2.2 分钟，等不到价格。

- 定时看盘对齐 K 线收盘（空仓：超短线 15 分钟、日内 1 小时、波段 4 小时；有仓：每根结构周期 K 线），Worker 不再自己定「多久后再看」。上面「`always` 尊重下次检查时间」一条被这条取代。
- 行情事件每个品种每小时最多叫醒 6 次，超过的并到下一次；持仓变化、仓位告警、用户留言、程序下单回报不受限。
- 新增「连续走线」事件；转折照旧。两者都只叫醒，不下单。
- 观察线只换真的变了的，到过一次在有效期内不重设。
- 删掉模拟盘的「预警 → 只读重估」模型调用：它和观察线、价格波动叫醒重复。上面第二条里的「模拟盘预警调用」已不存在。
- 页面上触发器和观察线合成「触发线」一页，用户可以自己加一条。
- Worker 结论里的观察线（`watch_levels`，只能叫醒）换成计划线（`lines`）：每轮必交，空仓时现价上下各至少一条；每条线带动作（进场 / 撤单 / 叫醒），到了由程序执行。一条进场线进场后其余进场线作废。
