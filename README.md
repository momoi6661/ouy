# Ouy — 欧易盯盘交易 Agent

欧易官方 Agent 授权登录（不用填 API Key），Agent 全自动盯盘：自己分析行情、判断入场/出场、调杠杆、开仓、加仓、减仓、移动止损、跑路。
后端 FastAPI + PydanticAI，交易能力来自欧易官方 Agent Trade Kit（180 个功能全部可用），前端 React。

## 启动

需要 Python 3.11+ 和 Node.js 18+。

```bash
# 1. 欧易官方组件（授权 + 交易通道）
npm install

# 2. 后端
python -m venv .venv
.venv/bin/pip install -e .          # Windows: .venv\Scripts\pip install -e .

# 3. 前端（只需构建一次）
cd web && npm install && npm run build && cd ..

# 4. 运行
.venv/bin/python -m ouy             # Windows: .venv\Scripts\python -m ouy
```

前三步只需要做一次，之后每次启动只运行第 4 步。

打开 <http://127.0.0.1:8899>。不登录也能看行情、K 线、盘口和知识库；要看账户、下单或启动 Agent 时，点右上角「登录欧易」→「获取授权码」，在浏览器里打开欧易授权页面，登录你的欧易账户并输入页面上的验证码即可。

`.env` 沿用原来的变量（见 `.env.example`）：

| 变量 | 说明 |
|---|---|
| `AI_MODEL` / `AI_BASE_URL` / `OPENAI_API_KEY` | 模型（OpenAI 兼容接口）|
| `AI_API_MODE` | `auto`（默认，自动判断）/ `responses` / `chat` |
| `LOCAL_PROXY_URL` | http 代理，访问欧易和模型接口都会走它；留空直连 |
| `OKX_SITE` | `global`（默认）/ `eea` / `us` / `tr` |
| `PORT` | 默认 8899 |
| `OUY_HOST` / `OUY_ACCESS_KEY` | 默认只监听本机。想用手机访问就把 `OUY_HOST` 设为 `0.0.0.0`，并且必须设置访问口令 |
| `KB_EMBEDDING_MODEL` | 知识库本地向量模型，默认 `BAAI/bge-small-zh-v1.5`，首次启动自动下载约 90MB |

`.env` 里**不需要也不应该**放欧易的 API Key。如果本机 `~/.okx/config.toml` 里配置过 API Key，官方组件会优先用它而跳过授权，请先移除。

## 它怎么工作

1. **欧易授权**：后端调用欧易官方 CLI 的 OAuth 设备授权，拿到授权页面链接和验证码。你在欧易的页面上登录并输入验证码后授权完成。令牌由官方组件保存在本机 `~/.okx/`，后端和网页都接触不到。
2. **盯盘**：点「启动盯盘」后，后端每 5 秒看一次行情和持仓。以下情况会叫醒 Agent 复盘：定时到点、价格波动超过阈值、触及 Agent 自己设的盯盘价位、进入计划入场区间、持仓出现或消失。
3. **Agent 复盘**：把多周期指标（5m/15m/1H/4H）、盘口、资金费率、持仓量、账户与持仓、上次计划，加上从知识库检索到的相关策略条目交给模型。模型直接调用工具开仓/加仓/减仓/平仓/调杠杆/移止损，并输出结论、交易计划和下一批盯盘价位。
4. **风控**（代码里写死的规则，Agent 改不了）：
   - 没有止损不下单；止损随开仓单一起挂到交易所，程序挂了也有效。
   - 仓位张数不由 Agent 决定：`张数 = 权益 × 单仓风险% ÷ (止损距离 × 合约面值)`，再受名义价值上限和可用保证金约束。
   - 止损只能收紧不能放宽；默认禁止亏损加仓；加仓必须先上移止损腾出风险额度。
   - 止损距离 × 杠杆过大（止损没到先爆仓）会被拒绝。
   - 当日亏损到上限后只许减仓/平仓；单仓浮亏触及紧急线时不等 Agent，直接市价平仓。
5. **三种权限**：全自动（默认）/ 下单前确认 / 只给建议。默认在**模拟盘**运行，切换实盘需要输入 yes 确认。

## 知识库（RAG）

`knowledge/` 下的 Markdown 就是 Agent 的交易手册：行情状态识别、八套策略（趋势回踩、突破回踩、区间高抛低吸、收敛突破、假突破反转、动量延续、拥挤度反转、趋势持仓）、入场出场、杠杆仓位、指标读法、K 线形态、持仓情景处理、事件风险、常见错误等。

- 切块后用「本地向量模型 + BM25 关键词」混合检索，纯本机运行，不消耗模型接口额度。
- 每次复盘前按当时的行情和持仓状态自动检索；Agent 也可以主动查询。
- `knowledge/trading_styles.md` 讲长线、波段、短线、超短线的区别，`knowledge/btc_correlation.md` 讲 BTC 对其他币的影响，也适合人读。
- 不管盯哪个币，Agent 复盘时都会带上 BTC 的走势；BTC 15 分钟内波动超过 0.8% 时，会立刻检查所有持仓。
- 想让 Agent 按你的方法做：把自己的 `.md` 放进 `knowledge/`，保存即生效。`knowledge/core/` 里的内容会固定写进系统提示词。

## 界面

- **Agent 工作台（首页）**：以 Agent 为中心。左边是团队（Router → 每个币的交易 Worker → 它的子代理和正在运行的策略，实时显示各自的状态）；中间是「等你同意」的事和实时活动流（每个 Agent 被什么唤醒、调了什么工具、交给了谁、做了什么操作、结论是什么，一步步滚动出来），下方直接对选中的 Agent 说话，Worker 正在思考时可以「插话」；右边是选中那个币的 K 线（画着它的计划和策略触发价）、结论、策略和目标。
- **交易**：行情列表（涨跌、最高杠杆，点 ★ 交给 Agent）、实时 K 线（持仓均价 / 止损 / 止盈 / 强平 / Agent 计划入场区间 / 盯盘价位都画在图上，按住止损、止盈线可以直接拖动修改）、持仓 / 挂单（每张挂单投入的保证金和合计）/ 已平仓盈亏、按比例平仓、一键反手、资产面板。布局固定：左行情，中间 K 线加下方持仓，右边对话 / Agent 盯盘 / 动态 / 下单；只有两条分隔线可以拖，双击恢复默认。
- **下单 / 盘口**：点图表上方的「做多 / 做空」弹出。可上下滑动的盘口（点价格填入限价）、市价 / 限价、全仓 / 逐仓、投入金额滑块、杠杆档位（按该币最高倍数列出，超过风控上限的置灰）、止损滑块（按亏掉投入保证金的百分比，默认值在设置里，初始 10%）、止盈。
- **Agent 对话**：每个币种一段独立的对话，记录会保存。让它做多、做空、加仓时，它给出方案卡片（入场区间、下单多少、止损、止盈、最多亏多少），点「确认执行」才下单，点「在图上显示」把方案画到 K 线上；平仓、减仓、移止损这类指令直接执行。它还能操作项目本身：切换图表品种和周期、增删盯盘品种、启停盯盘、给某个币单独设交易风格、改权限和风控（放宽需要你点确认）、替你填好下单窗。每条回答上方可以展开看它调用了哪些工具。
- **设置**：模拟盘/实盘、Agent 权限（可以按开仓、加仓、调杠杆、移止损、减仓、平仓、撤单分别设成自动 / 先问我 / 不允许）、思考强度、交易风格（超短线 / 日内短线 / 波段，决定它看的周期、复盘频率和止损宽度）、盯盘列表、风控参数、盯盘节奏、给 Agent 的额外交代、全部日志。
- **知识库**：文档列表和检索测试。
- **欧易全功能**：欧易官方开放的全部 180 个功能（行情、账户、现货、合约、期权、理财、网格/定投机器人、新闻情绪、聪明钱…），填参数即可调用。

## 用 Docker 运行（方便开关）

需要先装好并启动 Docker Desktop。在项目目录里：

```text
docker compose up -d          # 启动（第一次会构建镜像，要几分钟）
docker compose down           # 关闭
docker compose logs -f        # 看日志
docker compose up -d --build  # 更新代码后重新构建并启动
```

启动后打开 `http://127.0.0.1:8899`。端口只发布到本机，局域网里的其他设备访问不到。

- **代理**：容器里的 `127.0.0.1` 是容器自己，所以代理默认写成 `http://host.docker.internal:7890`（宿主机的 7890 端口）。后端、欧易官方组件、模型调用、知识库模型下载和构建镜像时的下载都走它。端口不是 7890 时，在 `.env` 里加一行 `DOCKER_PROXY_URL=http://host.docker.internal:你的端口`；不需要代理就写 `DOCKER_PROXY_URL=`（等号后面留空）。连不上时，在代理软件里打开「允许局域网连接」。
- **数据**：`data/`（数据库、日志、知识库缓存）和 `knowledge/` 直接挂载进容器，和不用 Docker 时是同一份，设置和历史记录都在。
- **欧易授权**：授权状态存在名为 `okx-home` 的 Docker 卷里，和 Windows 上的授权是分开的，第一次用 Docker 启动要在页面上重新授权一次，之后重建容器不用再授权。`docker compose down -v` 会连授权一起删掉。
- **不要同时开两个**：Docker 版和 `.venv\Scripts\python -m ouy` 用同一个端口和同一份数据，只能开一个。
- pip 下载慢时可以在 `.env` 里加 `PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` 再构建。

## Agent 团队（Super-agent 架构）

当前实现与 DeepSeek Harness 原文的对应、已修问题和剩余架构缺口见 [实现核对](docs/superagent-review.md)。

**日常只需要和 Router 对话**。SuperAgent 指整套协作架构，不是 Router 之外的另一个对话对象。例如：「汇总 ETH、SOL 的计划，区分挂单和已成交，不改仓位」。Router 查状态或委派后给你一个答复；不要把“已交给 Worker”当成“交易已执行”。

工作台只有一个 Router 对话入口，不需要先选模式：

| 用法 | 实际执行 |
| --- | --- |
| 输入 `/简报` | 直接列出当前环境各盯盘品种最近落库的复盘时间、计划和当轮回执，不唤醒 Worker。 |
| 问「ETH 上次为什么没进场？」 | Router 优先根据已有状态回答，需要新分析时才委派。 |
| 交代目标或请求操作 | 在同一个对话中处理，交易仍按已有权限和确认规则执行。 |

**不用会选策略。** 直接告诉 Router：「这两小时盯 ETH。我平时偏好限价，不追涨；这次没有合适机会就等。」之后输入 `/简报` 查看上次选了什么、程序如何处理、下一步关注哪个价位。盈利目标不是必须成交的指标，也不会自动提高权限。

**观察、选策、触发不是一件事。** 基础观察器采集走势，在量化节点按 5 分钟 K 线保留最近的判断；关快判不等于关观察。策略描述“什么行情用什么打法”，程序算候选，Worker 结合目标选或放弃。界面里的自定义“记录器”实际上是一种指标触发规则：只有你或 Worker 配了规则，才会在条件发生变化时通知或执行指定操作。采样本身不授权交易，关快判也不会撤销已经布置的独立策略。指标缺失或太旧时，触发规则等待有效采样，不把断流当成一次状态变化。

**开盘记录器。** 程序按盯盘节拍使用已有报价，对照场开、开盘前完整一小时及当前 5 分钟 K 线开盘，不另外轮询交易所。报价按环境、品种、分钟聚合保留首价、最高、最低、末价和样本数，随运行记录按保留天数清理。Worker 拿到当时的报价、开盘参照和最近六个有采样的分钟，不把轮询高低当成交易所逐笔高低。没有覆盖开盘、报价陈旧或 K 线刚切换时不猜缺失值。

**持仓轨迹与保盈线。** 程序给每笔仓按初始止损距离（R）记浮盈最高点、最深回撤和现在的位置，存库，重启不丢；Worker 复盘、平仓复盘和量化节点都看得到。浮盈最高到过约 0.5R，程序直接把止损移到入场价加往返成本，盈利单不再变成亏损单，模型出错时也照样执行；1R 保本规则不会把它往回放。Worker 可以按笔用 manage 的 `lock_r` 改线或关掉。5 分钟图出现和持仓相反的结构转折时，浮盈里先锁住，并叫醒 Worker 判断入场理由还在不在，不自动平仓。依据见 `knowledge/evidence.md`。

**按行情选打法。** 自动档每轮先判断局面：趋势只给顺势回踩，震荡只给区间两头，刚反转只给变盘后回踩，大方向和结构周期打架时不给入场候选。Worker 看到的【行情判断】和候选位是同一套。离场默认：0.5R 保盈线、第一目标平一半、1R 保本、超时离场。回测对比见 `knowledge/evidence.md`「按行情选打法」。

**转折雷达。** 按顺序检查三关：扫掉前 4 小时高低点后收回、动能背离、收盘反向越过摆动点。走到第几关显示在量化节点和 Worker 输入里，也可以作为记录器数据 `turn_stage`。回测里单凭它进场不赚钱，用来判断旧方向是否失效和新方向的回踩位。

**风格示意图。** 知识库页顶部的「交易风格和打法示意图」用简图说明超短线、日内、波段以及常用打法各自赚的是哪一段钱、在哪进、止损和目标放哪。

**转折位不必等下一根 K 线才看。** 对最近已收盘确认的 5 分钟突破，每次轮询用新报价核对。连续两个不同时间的报价退回关键位另一侧、超出波动与点差缓冲，就记录“疑似假突破”；重新站回也记录。先更新 `shift_failure`，再检查已有的指标触发规则。首次失守和恢复及时通知可工作的 Worker，同一结构随后来回穿越仍记录，但通知间隔至少一分钟。没有预先配置规则时，这条预警自身不下单。

**持仓失效与反手分开。** 新计划可选填入场和止损之间的 `review_level`，成交后按该计划风格的结构周期（5 分钟 / 15 分钟 / 1 小时）复核。盘中刺穿不算；持仓管理开始后完整一根 K 线收过该位，只通知 Worker 一次，不自动平仓或反手。原硬止损照常工作。另行布置的止损反手需要核对原持仓对应的交易所止损触发记录和整笔成交回执，仍要等反手触发价。止盈、手动退出、部分成交或无法确认来源不会因为价格继续走就被当成止损；回执核验重试最多 30 秒。

- 看盘不用换聊天对象。点量化节点看读数和记录器，点持仓看仓位，点策略节点看对应规则。只有在输入框旁明确选择某个 Worker，下一条才直接发给它。
- 主对话默认收起团队活动，审批卡和错误仍然可见。“查看团队动态”能回看过程，不会唤醒任何 Worker。
- 想减少模型调用，使用“事件唤醒”并开启软事件过滤。空仓且无新变化时，连续跳过定时复盘不会强制叫醒；定时看盘对齐 K 线收盘（空仓：超短线 15 分钟、日内 1 小时、波段 4 小时一次；有仓：每根结构周期 K 线一次），两次之间只有事件能叫醒 Worker；“每次都看”只是不做软事件过滤。行情事件每个品种每小时最多叫醒 6 次（可调），超过的并到下一次。量化采样并不代表已发单；快判是否可以提交还取决于方向授权、交易权限和风控。

- **Router**：常驻，负责和你对话、看全局、分派任务，自己不下单。事件分两级过滤：触及盯盘价位、成交、持仓变化直接唤醒 Worker；价格波动、定时这类先由 Router 判断值不值得唤醒。
- **每个币一个小组**：交易 Worker（唯一能下单的，带独立记忆）加情报 Worker（不能下单，只查资金费率、持仓量、聪明钱多空、新闻和事件，写成简报给交易 Worker）。
- **直通路由**：对话区可以选「对 Router 说」或「对这个币的 Worker 说」。Worker 发现机会或对仓位有建议时会主动发到这个币的对话区。
- **按笔记账**：同一个币可以有几笔不同风格的仓位，每笔有自己的止损止盈；Worker 每次被唤醒都要对每一笔给出结论（继续拿 / 收紧止损 / 减仓 / 加仓 / 平仓）。欧易里看到的仍是一个合并持仓。
- **可配置**：Agent 设置里可以改出手尺度（保守 / 均衡 / 积极）、Router / Worker / 情报 Worker 的模型、定时看盘时没变化要不要跳过；盯盘页「Worker 总览」里可以单独暂停、唤醒某个币的 Worker 或给它换模型，「任务」面板列出每次唤醒和被过滤掉的事件。
- **子代理**：交易 Worker 是小组的组长，手下三个不能下单的子代理：情报（资金费率、持仓量、新闻、情绪）、聪明钱（顶级交易员的多空和持仓）、风险复核（下单前复核敞口、止损和强平距离）。情报和聪明钱定时更新，Worker 也可以自己随时派；大仓位、高杠杆或逆势补仓前它会先让风险复核看一遍。
- **策略执行器（快的一层）**：模型想一次要几十秒到几分钟，行情等不了。所以 Worker 只负责判断和布置，「到价就做」的事交给策略执行器：按盯盘间隔（默认 3 秒）检查，条件满足立刻下单并按规则管理，不调用模型，每一笔仍然过硬性风控。现有策略：突破追单、回踩进场、区间两头、移动止损 / 分批止盈、翻倍补仓（无限子弹）、网格。权限是「先问我」时，策略要你点「同意启用」才开始运行。
- **建议就是工具调用**：Agent 想做什么就直接调用那个工具并填好参数。有权限的直接执行；要你同意的（权限是「先问我」或「只给建议」），这次调用原样挂起，变成一张「同意执行」的卡片（用的是 PydanticAI 自带的人工批准机制）。你点同意，执行的就是它那次调用；同意或拒绝的结果都会回到 Agent 手上，它从那里接着做，不是提完就不管。10 分钟没决定自动作废。
- **排队和插话**：同一个 Worker 一次只做一件事，它正在复盘时交来的任务排在后面，做完马上接着做；不同的币并行（上限在设置里，用的是 PydanticAI 自带的并发限制和排队）。Worker 正在思考时你或 Router 可以插话，它下一步就读到；它空闲时留言进信箱，被唤醒时先读。
- **目标**：直接对 Router 说目标（「今天 BTC 做超短线，最多亏 100 U」），它拆给对应币种的 Worker，之后每次复盘都带着这个目标；亏损到上限系统自动撤策略、撤单、平仓并停手。
- **入场方式**：设置里可以选市价优先（默认）/ 限价优先 / Agent 自己定。Agent 的限价单离现价超过风格允许的距离会被拒绝，挂单太久没成交会叫醒 Worker 处理。
- **你手动开的仓**：默认 Agent 只给建议，减仓、平仓、改止损都要你点确认才执行（包括在欧易 App 里开的仓；紧急平仓线对这些仓也只提醒不平）。在 Agent 设置的权限里可以关掉。
- **两头挂单**：区间上下沿各挂一张限价单时，一边成交后另一边自动撤掉。
- **省 token**：事件模式下，定时复盘时价格几乎没动、离关键价位都远，直接按规则跳过，不调用模型。复盘连续失败时自动唤醒统一退避 2、4、8、15 分钟；期间保留事件，行情采样、已授权触发器和程序保护照常运行。Watchdog 每 15 秒检查存活、每分钟巡检账户，模型复盘在独立任务里运行。
- **Watchdog**：盯盘循环停跳或某个 Worker 卡住时自动恢复。
- **查错误**：失败任务、工作台活动和盯盘面板可展开详情，查看新记录的上游错误正文、异常类型和调用位置；已被截短的旧记录只能查看当时保存的内容。进行中的复盘会标明下方是“上次完成”的报告。
- **模拟盘测不准的币**：某个币在模拟盘里价差过大或 K 线走平时，Worker 总览会标出「模拟盘测不准」，Agent 在它上面每笔风险压到四分之一。
- **模拟盘行情**：欧易模拟盘有自己独立的盘口，和真实市场对不上。K 线上方可以切换「模拟盘行情 / 真实行情」；模拟盘下 Worker 用真实市场判断方向，下单价位仍按模拟盘价格。

## 须知

- Agent 的判断会出错，合约交易可能亏光保证金。请先在模拟盘观察足够长的时间，再决定是否切实盘，并把风控参数设成自己能承受的水平。
- 一轮复盘可能因工具调用或审批续跑请求模型多次。「工作台 → 总览 → Worker 的结论」显示模型回报的缓存读取量、输入总量与首请求读取量；只有后续工具步骤命中不等于跨轮命中。旧记录没有输入总量时不估算比例。
- 这里的缓存是模型服务端的**输入前缀缓存**，不是复用上一轮回答。复盘和审批续跑沿用同一品种的路由键；请求先放固定规则和本次获取的已收盘 K 线（长周期在前），再放叫醒原因、盘中 K 线、账户与最新报价。规则、收盘数据或模型变化都会影响可复用长度；服务端不保证命中。见 [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching)。
- Agent 的自动交易目前只做 U 本位永续合约；其他品种可以在「欧易全功能」里手动操作。
